REVERSIBLE ADDERS FOR VIVADO
============================

What is here
------------
  src/rev_gates.v          gate library: NOT, Feynman, Toffoli, Peres, TSG, R2
  src/rev_adders.v         the five 4-bit modules of Section 5 (as built and simplified)
  src/rev_adders_wide.v    56 modules: seven designs x 4, 8, 16, 32 bits x as built / simplified
  sim/tb_rev_gates.v       checks every gate on every input
  sim/tb_rev_adders.v      4-bit modules of Section 5; the first 200 ns are the
                           four named cases of the waveform figure (Fig. 6)
  sim/tb_wide_4.v          all 512 inputs of the fourteen 4-bit modules
  sim/tb_wide_8.v          900 vectors (corner cases, then random) for the 8-bit modules
  sim/tb_wide_16.v         the same for 16 bits
  sim/tb_wide_32.v         the same for 32 bits
  sim/tb_demo_8.v          four named 8-bit additions on four designs, for waveform screenshots
  create_project.tcl       makes the Vivado project
  run_all_tests.tcl        runs all seven testbenches
  synth_one.tcl            synthesizes one module and writes reports
  synth_all.tcl            synthesizes (and routes) a list of modules; reports/summary.csv
  screenshot_schematic.tcl opens the RTL schematic of one module
  open_project_if_needed.tcl  used by the scripts above: opens the project after a restart
  VIVADO_GUIDE.pdf         step-by-step procedure, reports and screenshots

Every testbench finishes before 1000 ns, the default run time of the Vivado
simulator, and ends with ALL TESTS PASSED in the Tcl Console.

Step by step (Vivado GUI)
-------------------------
1. Unzip this folder somewhere whose path has no spaces, for example C:/rev/verilog.
2. Start Vivado. Choose Tools > Run Tcl Script... and select create_project.tcl.
   The project opens. (Or, in the Tcl Console:  source C:/rev/verilog/create_project.tcl )
3. In the Flow Navigator choose SIMULATION > Run Simulation > Run Behavioral Simulation.
   This runs tb_rev_adders. Look at the Tcl Console at the bottom: each module
   prints "wrong answers: 0 of 516", then ALL TESTS PASSED.
4. Waveform: the simulation window shows the testbench signals a, b, cin and the
   outputs. Zoom to 0-200 ns to see the four named cases (5+3, 15+1, 10+5, 9+9+1).
   To add the signals of one adder, expand dut1 ... dut5 in the Scope window and
   drag signals into the waveform.
5. Another testbench: in the Sources window open Simulation Sources > sim_1,
   right-click tb_wide_8 (for example) > Set as Top, then Run Behavioral
   Simulation again. Or run all six at once: Tools > Run Tcl Script... >
   run_all_tests.tcl.
6. Optional, FPGA synthesis of one module: edit the line "set top ..." in
   synth_one.tcl, then Tools > Run Tcl Script... > synth_one.tcl. The reports
   (LUT count, longest input-to-output delay) are written to the folder reports.

Expected output (tb_wide_32, the others look alike)

  cla_blocks_32_simplified   wrong answers: 0 of 900

Module names
------------
  4-bit modules of Section 5 (rev_adders.v):
    cla_as_built, cla_simplified, cla_carry_as_built, cla_carry_simplified, rca_peres
  Modules of Sections 6 and 7 (rev_adders_wide.v), <n> = 4, 8, 16 or 32:
  CLA blocks after Kumar et al. [11]   cla_blocks_<n>_as_built    cla_blocks_<n>_simplified
  TSG ripple-carry                     tsg_rca_<n>_as_built    tsg_rca_<n>_simplified
  Peres ripple-carry                   peres_rca_<n>_as_built    peres_rca_<n>_simplified
  Cuccaro                              cuccaro_<n>_as_built    cuccaro_<n>_simplified
  VBE                                  vbe_<n>_as_built    vbe_<n>_simplified
  Draper carry look-ahead              draper_<n>_as_built    draper_<n>_simplified
  Hybrid CLA (Phase 11)                hybrid_<n>_as_built    hybrid_<n>_simplified

Ports
-----
  a[n-1:0], b[n-1:0]   operands
  cin                  carry input (CLA blocks, TSG, Peres and hybrid designs only)
  sum[n-1:0], cout     result
  clean                Cuccaro, VBE and Draper only: 1 when every operand line is
                       restored and every ancilla line is back at 0. The testbench
                       counts a wrong answer if it is not 1.

What the results mean
---------------------
Simulation checks that each circuit adds correctly; this repeats, in a hardware
language, the exact proofs of the paper. Synthesis maps each module to ordinary
FPGA logic. Vivado optimizes the whole function, so as-built and simplified
versions often give similar LUT counts. Those numbers are not reversible-logic
measures (quantum cost, T-count, ancilla) and should not be presented as
savings of the reversible circuits.

These files were generated by verilog_wide.py and verilog.py of the project and
were checked with the Icarus Verilog simulator, not with Vivado itself.
